# Momo Store

Интернет-магазин пельменей. Бэкенд на Go, фронтенд на Vue.js.

## Архитектура

```
Browser
  ├── :80  → frontend (nginx, статика Vue.js)
  └── :8081 → nginx-lb (балансировщик) → backend × 2 (Go API)
```

- **frontend** — nginx раздаёт собранный SPA, доступен на порту `80`
- **nginx-lb** — nginx-балансировщик, проксирует запросы на два инстанса бэкенда, порт `8081`
- **backend** — Go-сервис (порт `8081` внутри сети), запускается в двух репликах

Сети изолированы: `frontend-net` и `backend-net`. Фронтенд-контейнер не имеет доступа к бэкенду на уровне Docker-сети — взаимодействие идёт через браузер пользователя.

## Запуск

### Требования

- Docker Engine 24+
- Docker Compose v2

### Подготовка

```bash
cp .env.example .env
```

При необходимости укажите в `.env` адрес бэкенда, который видит браузер:

```
VUE_APP_API_URL=http://localhost:8081
```

### Production

```bash
docker compose up -d --build
```

Приложение доступно:
- Фронтенд: http://localhost/momo-store/
- API: http://localhost:8081

### Development

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build
```

Отличия: одна реплика бэкенда, debug-логи, без ограничений ресурсов и read-only ФС.

### Масштабирование бэкенда

```bash
docker compose up -d --scale backend=3
```

nginx-lb автоматически распределит нагрузку между инстансами через Docker DNS.

### Остановка

```bash
docker compose down
```

## Образы

| Образ | Базовый образ (финальный) | Приблизительный размер |
|-------|--------------------------|------------------------|
| momo-store-backend | alpine:3.19 | ~20 MB |
| momo-store-frontend | nginx:1.25-alpine | ~25 MB |

Multi-stage сборка: артефакты билда (`golang:1.21-alpine`, `node:18-alpine`) не попадают в финальный образ. Финальные образы содержат только исполняемый файл или статику + nginx.

## Безопасность

**Контейнеры:**
- Все сервисы запускаются от непривилегированного пользователя (`app` / `nginx`)
- `read_only: true` — корневая ФС только для чтения; временные данные через `tmpfs`
- `cap_drop: ALL` — все Linux capabilities сброшены, добавлены только необходимые
- `security_opt: no-new-privileges:true` — запрет эскалации привилегий

**Секреты:**
- Чувствительные данные передаются через Docker Secrets (монтируются в `/run/secrets/`)
- Никаких паролей и токенов в переменных окружения или слоях образа

**Образы:**
- Минимальные базовые образы (alpine, nginx-alpine)
- Сканирование уязвимостей через Trivy в CI/CD (см. `.github/workflows/deploy.yaml`)
- Финальные образы не содержат компиляторов, пакетных менеджеров и инструментов разработки

**Сеть:**
- Изолированные сети для разных групп сервисов
- Открыты только необходимые порты (80 и 8081 на хосте)

## CI/CD

`.github/workflows/deploy.yaml` при каждом пуше в `main`:
1. Собирает и пушит образы на DockerHub
2. Сканирует образы на уязвимости (Trivy)
3. Проверяет запуск через Docker Compose
